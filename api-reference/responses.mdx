# POST /responses

Responses 接口适合使用新版 OpenAI Responses API 风格的客户端。它把输入、工具调用和多模态能力放在更统一的请求结构中。

## 请求

```bash
curl https://api.routestack.cn/v1/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_ROUTESTACK_TOKEN" \
  -d '{
    "model": "gpt-4o-mini",
    "input": "用一句话总结 RouteStack。"
  }'
```

## 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `model` | string | 是 | 要调用的模型名称 |
| `input` | string / array | 是 | 输入内容 |
| `stream` | boolean | 否 | 是否流式输出 |
| `temperature` | number | 否 | 控制输出随机性 |

## 响应示例

```json
{
  "id": "resp_example",
  "object": "response",
  "output_text": "RouteStack 将多模型调用统一到一个稳定的 API 入口。"
}
```

## 与 chat completions 的区别

| 接口 | 更适合的场景 |
| --- | --- |
| `/v1/chat/completions` | 传统聊天、通用兼容、现有 OpenAI SDK 迁移 |
| `/v1/responses` | 新版 Responses API 风格、统一输入结构、多模态或工具调用场景 |

如果你不确定应该使用哪个接口，建议先使用 `/v1/chat/completions`，它的生态兼容性更强。

## 兼容说明

不同上游模型供应商对 Responses 风格接口的支持可能不同。RouteStack 会尽量做兼容转发，但如果遇到模型不支持、参数不兼容或返回结构不同的问题，可以优先切换到 `/v1/chat/completions`。

## 排查建议

- 确认模型支持 Responses 风格调用。
- 确认 API Key 有权限调用该模型。
- 确认账号余额和令牌额度充足。
- 在控制台使用日志中查看上游错误信息。
