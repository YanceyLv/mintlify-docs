# API 总览

RouteStack 的 API 设计目标是尽量兼容 OpenAI SDK 和常见 AI 客户端。大多数情况下，你只需要替换 `baseURL` 和 `apiKey`，原来的请求结构可以继续使用。

## Base URL

正式环境：

```text
https://api.routestack.cn/v1
```

本地开发：

```text
http://127.0.0.1:3000/v1
```

如果你的网站和接口部署在同一个域名下，也可以使用当前站点显示的 API 地址作为入口。

## 认证方式

所有 API 请求都需要在请求头中携带 API Key：

```http
Authorization: Bearer YOUR_ROUTESTACK_TOKEN
```

API Key 可以在控制台的令牌管理页面创建。不同令牌可以设置不同额度、模型权限和有效期。

## 常用接口

| 接口 | 用途 |
| --- | --- |
| `GET /models` | 获取当前 API Key 可用的模型列表 |
| `POST /chat/completions` | OpenAI 兼容的聊天补全接口 |
| `POST /responses` | Responses 风格的模型响应接口 |

## 请求格式

请求体通常使用 JSON：

```http
Content-Type: application/json
```

推荐所有业务系统都显式设置 `Content-Type`，这样更容易排查兼容性问题。

## 常见错误

| 状态码 | 常见原因 | 处理方式 |
| --- | --- | --- |
| `401` | API Key 缺失或无效 | 检查 `Authorization` 请求头 |
| `402` | 余额不足或额度不足 | 充值或调整用户额度 |
| `403` | 当前用户或令牌无权使用模型 | 检查用户分组、令牌限制和模型权限 |
| `429` | 触发频率限制 | 降低并发或调整限流配置 |
| `5xx` | 上游渠道异常或平台内部错误 | 查看控制台使用日志和渠道状态 |

## 排查顺序

1. 确认 Base URL 是否正确。
2. 确认 API Key 是否有效。
3. 确认模型名称是否在 `GET /models` 返回列表中。
4. 确认账号余额、分组权限和令牌额度是否足够。
5. 到控制台的使用日志查看失败请求详情。
